# Website Update Guide

This guide explains how to update the homepage, news, publications, group section, and blog content for this repository.

## Project Structure

- Main site pages:
  - `index.html` - homepage, profile, short News preview, short Publications preview, Group section.
  - `news.html` - complete News source page.
  - `publications.html` - complete Publications source page.
- Shared frontend files:
  - `style.css` - shared layout, buttons, badges, navigation, publication styles.
  - `script.js` - homepage preview loading, News expand/collapse, publication filtering.
  - `images/` - profile and project images.
- Blog source files:
  - `blog-src/`
- Blog output:
  - Generated by GitHub Actions during deployment.
  - Local output may appear in `blog/`, but it should not be committed.

## Core Content Rule

Keep long content in one place:

- Update full News only in `news.html`.
- Update full Publications only in `publications.html`.
- `index.html` loads preview content from those pages with JavaScript.

Do not duplicate full News or full Publications manually in `index.html`.

Because the homepage uses `fetch()` to load content from `news.html` and `publications.html`, test through a local HTTP server or GitHub Pages. Opening `index.html` directly with `file://` may block the dynamic preview loading.

## 4. Add News

The complete News list is in:

```text
news.html
```

The homepage News block in `index.html` is only a preview container:

```html
<div id="news" class="section news news-preview" data-source="./news.html" data-preview-count="5">
```

How it works:

- `data-source="./news.html"` tells `script.js` where to load full News from.
- `data-preview-count="5"` means the homepage initially shows the first 5 News items.
- `script.js` copies all `<li>` items from `.news-full ul li` in `news.html` into the homepage preview.
- `Show More` expands the homepage News list in place.
- `Show Less` folds it back to the preview count.

To add a News item:

1. Open `news.html`.
2. Search for:

```html
<div id="news" class="section news news-full">
```

3. Add the newest `<li>` item at the top of the `<ul>`.

For the latest item, use:

```html
<li>
    <span class="new-badge">NEW</span>
    07/2026 - Your new update here.
</li>
```

For older items, do not use the `NEW` badge:

```html
<li>
    07/2026 - Your older update here.
</li>
```

Notes:

- Put the newest item first.
- Usually only the first/latest item should have:

```html
<span class="new-badge">NEW</span>
```

- Do not add the same News item to `index.html`.
- `news.html` remains a complete source page, but the top navigation sends users to `./index.html#news`.

## 5. Add Publications

The complete publication list is in:

```text
publications.html
```

The homepage Publications block in `index.html` is only a selected-paper preview container:

```html
<div id="paper" class="section research research-preview" data-source="./publications.html">
```

How it works:

- `data-source="./publications.html"` tells `script.js` where to load papers from.
- `script.js` copies all `.research-full .research-proj[data-select="True"]` papers from `publications.html`.
- The full `publications.html` page has filters for selected papers, topics, and year.
- `Show Selected Papers` is disabled by default, so the full Publications page initially displays all papers.

To add a new paper, copy an existing `research-proj` block in `publications.html` and modify it.

Current block structure:

```html
<div class="research-proj" data-year="2026" data-topics="LLM/MLLM Foundation Models" data-select="True">
    <a href="project-or-paper-url" class="research-thumb">
        <img src="./images/projects/your-image.png" alt="" />
    </a>
    <a href="project-or-paper-url" class="research-proj-title">Paper Title</a>
    <p>
        Author list <br>
        ICML 2026 <br>
        <a href="paper-url">Paper</a>&nbsp;&nbsp;&bull;&nbsp;&nbsp;
        <a href="code-url">Code</a>
    </p>
</div>
```

Field meanings:

- `data-year="2026"` controls the year filter and the displayed year in the normalized meta row.
- `data-topics="..."` controls the topic filter. It is not displayed directly in the paper list.
- `data-select="True"` marks the paper as selected and includes it in the homepage list.
- `data-select="False"` excludes the paper from the homepage list. It remains visible by default on the full page.
- The venue/report line is the text between the first and second `<br>`, for example `ICML 2026` or `Tech Report`.
- Resource links after the second `<br>` are collected into the final meta row, for example `Paper`, `Code`, `HF`, or `Project`.

Current topic options:

```text
LLM/MLLM Foundation Models
Efficienct AI
Neural Architecture Design and Search
Classical Computer Vision
```

Important publication rules:

- Keep the list order in `publications.html` as the intended source order.
- Do not display topic text manually inside the paper body.
- To mark a paper as selected, set `data-select="True"`.
- To remove a paper from the selected default view, set `data-select="False"`.
- Put paper images under:

```text
images/projects/
```

Then reference them like:

```html
<img src="./images/projects/your-image.png" alt="" />
```

If no real image is ready, use an existing placeholder style or a temporary existing image until the final asset is added.

### Publication Highlights And Notes

Some publications have additional information such as an oral presentation, featured-paper designation, or challenge ranking. Keep this information in `publications.html`; `script.js` preserves and formats it when it builds the final publication meta row.

Use a `<strong>` element for a short highlight that belongs in the same row as the year, venue, and resource links:

```html
ECCV 2022 <br>
<strong>Oral Presentation</strong>&nbsp;&nbsp;&bull;&nbsp;&nbsp;
<a href="paper-url">Paper</a>&nbsp;&nbsp;&bull;&nbsp;&nbsp;
<a href="code-url">Code</a>
```

Supported examples include:

```text
Oral Presentation
Featured Paper
```

`normalizePublicationMeta()` converts these values to `.pub-highlight` labels. They appear after the venue and before `Paper`, `Code`, or other resource links.

Use `.publication-note` for a complete linked remark such as a challenge result. Put it after the resource links and keep the ranking inside `.pub-highlight`:

```html
CVPR 2019 <br>
<a href="paper-url">Paper</a>&nbsp;&nbsp;&bull;&nbsp;&nbsp;
<a href="code-url">Code</a><br>
<span class="publication-note">
    <span class="pub-highlight">
        <a href="challenge-url">Rank #1</a>
    </span>
    in <a href="challenge-url">VOT-2019</a> Challenge RGB-D Track
</span>
```

Publication note rules:

- Use a short highlight for labels such as `Oral Presentation` and `Featured Paper`.
- Use a publication note for a full sentence such as `Rank #1 in VOT-2019 Challenge RGB-D Track`.
- Keep the challenge or award URL on both the ranking and event name when the old page provides both links.
- Place notes after the second `<br>` and after the normal resource links.
- Do not add note links as separate `Paper` or `Code` resources. `script.js` keeps links inside `.publication-note` together with the note text.
- When restoring historical remarks, compare the matching paper in `old_homepage/publication.html` by title.

The relevant styles are:

```text
.pub-highlight
.publication-note
```

## 6. Publication Filtering

Publication filters are created by `script.js`, not hardcoded in `publications.html`.

The filter controls are:

- `Show Selected Papers`
- `Filter by Topics`
- `Filter by Year`

The topic options are defined in `script.js` inside `initPaperFiltering()`:

```js
var topicOptions = [
    ['all', 'All Topics'],
    ['LLM/MLLM Foundation Models', 'LLM/MLLM Foundation Models'],
    ['Efficienct AI', 'Efficienct AI'],
    ['Neural Architecture Design and Search', 'Neural Architecture Design and Search'],
    ['Classical Computer Vision', 'Classical Computer Vision']
];
```

If you add a new topic category:

1. Add the topic string to the paper's `data-topics`.
2. Add the same topic string to `topicOptions` in `script.js`.
3. Test the filter on `publications.html`.

## 7. Shared JavaScript Responsibilities

`script.js` handles:

- Homepage News loading from `news.html`.
- Homepage selected Publications loading from `publications.html`.
- News `Show More` / `Show Less`.
- Publication meta-row normalization.
- Publication highlights and linked note preservation.
- Publication filters.
- Re-scrolling to hash anchors after dynamic preview content loads.

Important functions:

```text
syncHomepageNews()
syncHomepagePublications()
initNewsToggle()
toggleNews()
normalizePublicationMeta()
initPaperFiltering()
filterPapers()
scrollToHashTarget()
```

Avoid duplicating this logic inline inside HTML pages.

## 8. Create A New Blog Post

Blog source files are stored in:

```text
blog-src/content/posts/
```

Use Hugo to create a new post:

```powershell
hugo new posts/my-new-post.md --source .\blog-src
```

This creates:

```text
blog-src/content/posts/my-new-post.md
```

The new file will contain front matter similar to:

```markdown
---
date: 2026-07-12T10:00:00+08:00
draft: true
title: My New Post
---
```

Write the blog content below the front matter:

```markdown
---
date: 2026-07-12T10:00:00+08:00
draft: true
title: My New Post
---

Write the post content here.
```

Important:

- `draft: true` means the post is a draft and will not be published by default.
- To publish the post, change it to:

```markdown
draft: false
```

## 11. Publish Blog Posts

Before publishing, make sure the post is not a draft:

```markdown
draft: false
```

Then commit and push:

```powershell
git add .
git commit -m "Add new blog post"
git push
```

GitHub Actions will automatically:

1. Install Hugo Extended.
2. Pull the PaperMod theme submodule.
3. Build the main site.
4. Build `blog-src/` into `/blog/`.
5. Deploy the complete site to GitHub Pages.

Production URLs:

```text
https://houwenpeng.com/blog/
https://houwenpeng.com/blog/posts/
```

## 12. GitHub Pages Setting

In the GitHub repository, set Pages to use GitHub Actions:

```text
Settings -> Pages -> Source -> GitHub Actions
```

After this is configured, do not manually commit the generated `blog/` directory.

The `blog/` directory is only for local testing. The production blog is generated by GitHub Actions.

### Blog Returns 404 After A Successful Workflow

If `https://houwenpeng.com/blog/` returns 404 even though `Deploy GitHub Pages` succeeds, check the Actions list. Seeing both of these workflows for the same `master` push usually means Pages is still using branch deployment:

```text
Deploy GitHub Pages
pages build and deployment
```

The automatically generated `pages build and deployment` job publishes the repository branch directly. Because generated `blog/` output is intentionally not committed, that deployment does not contain the Blog and can overwrite the custom Actions deployment.

Fix it in the repository settings:

1. Open `Settings -> Pages`.
2. Under `Build and deployment`, change `Source` to `GitHub Actions`.
3. Open `Actions -> Deploy GitHub Pages`.
4. Select `Run workflow`, choose `master`, and run it again.
5. Confirm that `https://houwenpeng.com/blog/` returns the Blog instead of 404.

The deployment workflow verifies that `_site/blog/index.html` exists before uploading the Pages artifact. If Hugo stops producing the Blog, the build will now fail explicitly instead of deploying an incomplete artifact.

## 13. Recommended Daily Workflow

For homepage, News, Group, or Publication updates:

```powershell
# Edit index.html, news.html, or publications.html
.\serve.ps1

# Check locally in the browser, then publish
git add .
git commit -m "Update website content"
git push
```

For blog updates:

```powershell
hugo new posts/my-new-post.md --source .\blog-src

# Edit blog-src/content/posts/my-new-post.md
# Change draft: true to draft: false when ready to publish

.\build-blog.ps1
.\serve.ps1

# Check locally in the browser, then publish
git add .
git commit -m "Add blog post"
git push
```

## Final Checklist

- Main site content is edited in `index.html`, `news.html`, and `publications.html`.
- News is updated once in `news.html`; homepage News syncs from it.
- Publications are updated once in `publications.html`; homepage selected papers sync from it.
- Blog content is edited in `blog-src/content/posts/`.
- Test through `.\serve.ps1`, not direct `file://`, when checking dynamic previews.
- Production deployment is handled by GitHub Actions.
- The generated `blog/` directory is local build output and should not be committed.
