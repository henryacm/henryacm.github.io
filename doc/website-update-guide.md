# Website Update Guide

This guide explains how to update the homepage, news, publications, and blog content for this repository.

## Project Structure

- Main site pages:
  - `index.html`
  - `news.html`
  - `publications.html`
- Shared frontend files:
  - `style.css`
  - `script.js`
  - `images/`
- Blog source files:
  - `blog-src/`
- Blog output:
  - Generated by GitHub Actions during deployment.
  - Local output may appear in `blog/`, but it should not be committed.

## 1. Update The Homepage Introduction

The homepage introduction is in:

```text
index.html
```

Search for:

```html
<div id="profile-intro">
```

This area contains the name, title, biography, contact links, and related profile information.

To update it:

1. Open `index.html`.
2. Search for `profile-intro`.
3. Edit the text, links, email, or profile details inside that block.
4. Save the file and refresh the local homepage.

Local preview URL:

```text
http://127.0.0.1:8000/index.html
```

## 2. Add Or Update Group Members

Group members are listed on the homepage:

```text
index.html
```

Search for:

```html
id="group"
```

You will find a section like:

```html
<div id="group" class="section group">
```

Existing member entries look like:

```html
<li><a href="https://houwenpeng.com/group.html">Minghao Chen</a> (PhD, Stony Brook Univ.)</li>
```

To add a new member, copy an existing line and update the name, link, and description:

```html
<li><a href="member-homepage-url">Member Name</a> (Role or affiliation)</li>
```

If the member does not have a homepage yet, use plain text:

```html
<li>Member Name (Role or affiliation)</li>
```

## 3. Add News

The full news list is in:

```text
news.html
```

The homepage automatically loads the latest news from `news.html`, so normally you only need to update `news.html`.

To add a news item:

1. Open `news.html`.
2. Find the existing news list.
3. Add the newest item at the top.

For the latest item, use:

```html
<li>
    <span class="new-badge">NEW</span>
    07/2026 - Your new update here.
</li>
```

For older items, do not use the `NEW` badge:

```html
<li>
    07/2026 - Your older update here.
</li>
```

Notes:

- Put the newest news item first.
- Only the first/latest item should usually have:

```html
<span class="new-badge">NEW</span>
```

- The homepage preview is loaded from `news.html`, so you do not need to duplicate the item in `index.html`.

## 4. Add Publications

The full publication list is in:

```text
publications.html
```

The homepage automatically loads selected publications from `publications.html`, so normally you only need to update `publications.html`.

To add a new paper, copy an existing publication block and modify it.

Template:

```html
<div class="research-proj" data-year="2026" data-topics="LLM/MLLM Foundation Models" data-select="True">
    <a href="paper-url">
        <img src="./images/projects/your-image.png" alt="Paper image">
    </a>
    <div class="research-info">
        <p class="research-title">
            <a href="paper-url">Paper Title</a>
        </p>
        <p>Author list</p>
        <div class="paper-meta">
            <span class="paper-year">2026</span>
            <span class="selected-badge">Selected</span>
            <a href="venue-url">ICML</a>&nbsp;&nbsp;&bull;&nbsp;&nbsp;
            <a href="paper-url">Paper</a>&nbsp;&nbsp;&bull;&nbsp;&nbsp;
            <a href="code-url">Code</a>
        </div>
    </div>
</div>
```

Field meanings:

- `data-year="2026"` controls the year filter.
- `data-topics="..."` controls the topic filter and is not displayed directly in the paper list.
- `data-select="True"` means the paper appears when `Show Selected Papers` is enabled.
- `data-select="False"` means the paper is hidden by default and appears when the selected filter is disabled.
- `<span class="paper-year">2026</span>` displays the year in the meta row.
- `<span class="selected-badge">Selected</span>` displays the selected label. Remove this line for non-selected papers.

Current topic options:

```text
LLM/MLLM Foundation Models
Efficienct AI
Neural Architecture Design and Search
Classical Computer Vision
```

If the paper has an image, put it under:

```text
images/projects/
```

Then reference it like:

```html
<img src="./images/projects/your-image.png" alt="Paper image">
```

## 5. Create A New Blog Post

Blog source files are stored in:

```text
blog-src/content/posts/
```

Use Hugo to create a new post:

```powershell
hugo new posts/my-new-post.md --source .\blog-src
```

This creates:

```text
blog-src/content/posts/my-new-post.md
```

The new file will contain front matter similar to:

```markdown
---
date: 2026-07-12T10:00:00+08:00
draft: true
title: My New Post
---
```

Write the blog content below the front matter:

```markdown
---
date: 2026-07-12T10:00:00+08:00
draft: true
title: My New Post
---

Write the post content here.
```

Important:

- `draft: true` means the post is a draft and will not be published by default.
- To publish the post, change it to:

```markdown
draft: false
```

## 6. Test Blog Locally

Build the blog locally:

```powershell
.\build-blog.ps1
```

Start the local server:

```powershell
.\serve.ps1
```

Open:

```text
http://127.0.0.1:8000/blog/
```

Post list:

```text
http://127.0.0.1:8000/blog/posts/
```

Single post example:

```text
http://127.0.0.1:8000/blog/posts/my-new-post/
```

To preview draft posts locally, build with drafts enabled:

```powershell
hugo --source .\blog-src --destination .\blog --baseURL "http://127.0.0.1:8000/blog/" --buildDrafts --gc
```

Then start the local server:

```powershell
.\serve.ps1
```

## 7. Publish Blog Posts

Before publishing, make sure the post is not a draft:

```markdown
draft: false
```

Then commit and push:

```powershell
git add .
git commit -m "Add new blog post"
git push
```

GitHub Actions will automatically:

1. Install Hugo Extended.
2. Pull the PaperMod theme submodule.
3. Build the main site.
4. Build `blog-src/` into `/blog/`.
5. Deploy the complete site to GitHub Pages.

Production URLs:

```text
https://houwenpeng.com/blog/
https://houwenpeng.com/blog/posts/
```

## 8. GitHub Pages Setting

In the GitHub repository, set Pages to use GitHub Actions:

```text
Settings -> Pages -> Source -> GitHub Actions
```

After this is configured, do not manually commit the generated `blog/` directory.

The `blog/` directory is only for local testing. The production blog is generated by GitHub Actions.

## 9. Recommended Daily Workflow

For homepage, news, or publication updates:

```powershell
# Edit index.html, news.html, or publications.html
.\serve.ps1

# Check locally in the browser, then publish
git add .
git commit -m "Update website content"
git push
```

For blog updates:

```powershell
hugo new posts/my-new-post.md --source .\blog-src

# Edit blog-src/content/posts/my-new-post.md
# Change draft: true to draft: false when ready to publish

.\build-blog.ps1
.\serve.ps1

# Check locally in the browser, then publish
git add .
git commit -m "Add blog post"
git push
```

## Core Rule

- Main site content is edited in `index.html`, `news.html`, and `publications.html`.
- Blog content is edited in `blog-src/content/posts/`.
- Production deployment is handled by GitHub Actions.
- The generated `blog/` directory is local build output and should not be committed.
